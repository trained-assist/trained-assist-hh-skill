## Сводка по серьёзности

- **P0: 1** — массовая отправка без подтверждения (в паре с вводящими в заблуждение кнопками баллов).

## Экран «Кандидаты» (`/hh/review`) — ядро аудита

### P0 — Массовая отправка не имеет подтверждения (в отличие от массового отказа)

- **Ожидание рекрутера:** массовое действие, необратимое наружу (сообщения уходят кандидатам), должно просить подтверждение с числом получателей.
- **Факт:** `sendAll()` (`src/hh-review-page-html.js:1006`) рассылает все отмеченные карточки **без единого подтверждения**. Подтверждение (`window.confirm`) появляется только если среди выбранных есть устаревшие черновики. При этом `rejectAll()` (`:1052`) подтверждает всегда: «Отказать N кандидатам?…». Асимметрия: отказ защищён, отправка — нет.
- **Воспроизведение:** на странице с 2+ отмеченными карточками нажать «Отправить (N)» → сообщения уйдут без диалога. Подтверждение появляется лишь при `data-stale="1"`.
- **Расхождение:** нарушен принцип «подтверждение необратимого/массового действия»; риск неожиданной массовой отправки.
- **Исправление:** добавить общий `confirm('Отправить N кандидатам? Каждому уйдёт его черновик.')` в `sendAll()` до цикла, как это уже сделано в `rejectAll()`.
- **Тест:** 2 отмеченные карточки → клик «Отправить (2)» → ожидаем confirm; после отмены — ни одного вызова `/hh/send`.

### P1 — Кнопки баллов 10..1 — скрытый механизм выбора на отправку

- **Ожидание:** надпись «Балл (округление до целого)» и ряд кнопок 10…1 читаются как **оценка** кандидата (или как фильтр).
- **Факт:** `toggleBucket(n)` (`:637`) — это **пакетный выбор карточек на отправку** по округлённому скору: клик по «10» отмечает галочкой «Отправить» у всех карточек со скором 10, повторный клик снимает. Кнопки баллов **никогда не трогают** галочки «Отказать».
- **Подтверждено реальными кликами** (`tests/audit/review-click.spec.cjs`): клик по «10» → `cb-3` (скор 10) `checked=true`; повторный клик → `checked=false`; `reject-cbs` остаются пустыми.
- **Расхождение:** надпись обещает оценку, а действие — массовый выбор на отправку. Рекрутер может случайно отметить кандидатов к отправке, думая, что просто ставит балл. В паре с P0 (нет confirm) это прямой путь к неожиданной массовой отправке.
- **Исправление:** переименовать в «Выбрать со скором N» / «Скор N → в отправку» и визуально отделить от оценки; либо сделать фильтром списка, не трогающим галочки.
- **Тест:** клик по «8» → отмечаются только карточки со скором 8; галочки «Отказать» не меняются.

### P1 — Область массовых действий = активная вкладка, но на это не указано

- **Ожидание:** «Выбрать все», «Отправить (N)», «Отказать (N)», «Перегенерировать все черновики» — рекрутер ожидает, что действие охватывает всех кандидатов вакансии.
- **Факт:** все эти функции оперируют только `.tab-panel.active` (`selectAll` `:650`, `toggleBucket` `:641`, `sendAll` `:1007`, `rejectAll` `:1053`, `regenerateAll` `:670`). На вкладке «Неотвеченные» счётчик и массовые действия относятся только к ней.
- **Подтверждено реальными кликами:** на вкладке «Неотвеченные» (3 карточки) «Выбрать все» → `selCount=3`, `sendAllBtn=«Отправить (3)»`, хотя всего на вакансии 3 кандидата — при большем числе расхождение будет видно.
- **Расхождение:** надпись «Отправить (N)» не говорит «на этой вкладке»; рекрутер может отправить не тех, или не отправить нужных.
- **Исправление:** в подпись счётчика добавить область («Отправить (N на этой вкладке)») либо явно предложить «применить ко всем откликам».
- **Тест:** вкладка «Неотвеченные» с K карточками из N → «Выбрать все» → счётчик = K, а не N.

### P2 — Нет «выбрать все на отказ»; асимметрия с отправкой

- **Факт:** `selectAll` и кнопки баллов работают только с `.card-cb` («Отправить»). Галочки `.reject-cb` («Отказать») можно поставить только вручную по одной. Кнопки «Отказать (N)» нет в тулбаре выбора.
- **Расхождение:** рекрутер, желающий отказать группе, вынужден кликать каждую карточку; при этом «Выбрать все» существует только для отправки.
- **Исправление:** добавить «Отказать все» (с подтверждением) либо сделать кнопки баллов управлять и отказом.
- **Тест:** на вкладке с K карточками «Отказать все» → все `.reject-cb` отмечены + confirm.

### P2 — «Перегенерировать все черновики» перезаписывает ручные правки без подтверждения

- **Факт:** `regenerateAll()` (`:668`) перегенерирует черновики всех активных карточек вкладки без `confirm`. Если рекрутер вручную правил текст в `msg-i`, он будет перезаписан.
- **Исправление:** подтверждение + пропуск карточек с ручной правкой (или явный чекбокс «включая отредактированные»).
- **Тест:** отредактировать `msg-0` → «Перегенерировать все» → confirm; после отмены текст не изменился.

### P2 — Stale-гард работает, но подсказка расплывчатая

- **Факт:** устаревший черновик показывает баннер «Старый черновик: обновите его по сценарию перед отправкой», галочку не ставит, кнопка отправки подсвечена (`data-stale="1"`), отправка требует confirm. Это правильно (PR #165).
- **Расхождение:** фраза «обновите его по сценарию» не говорит, как именно (путь — «Перегенерировать»). Мелочь.
- **Исправление:** в баннере назвать действие: «нажми "Перегенерировать"».

### P3 — После отправки карточка блокируется целиком, включая «Отправить отказ»

- **Факт:** `markDone(i)` (`:657`) отключает все `input[type=checkbox]` и `button` карточки. Рекрутер, отправивший сообщение, не сможет отказать этому кандидату без перезагрузки.
- **Исправление:** оставить активной кнопку «Отправить отказ» (или объяснить, почему заблокировано).

## Экран «ATS воронка» (`/hh/ats-editor`)

### P1 — Нет защиты несохранённых правок

- **Ожидание:** отредактировал этапы/критерии и ушёл со страницы → правки не должны теряться молча.
- **Факт:** в редакторе нет `beforeunload` и индикатора «есть несохранённые изменения». Единственный `beforeunload` в модуле — в review-странице и только для массовой генерации (`:480`). Переход по навигации или перезагрузка теряют правки без предупреждения.
- **Исправление:** отслеживать `dirty` при любом изменении полей/этапов, показывать индикатор и `beforeunload`.
- **Тест:** изменить поле → перейти на другую страницу → ожидаем предупреждение.

### P2 — «↺ Re-run Funnel» в подсказке называет внутренний инструмент

- **Факт:** после сброса тост «Funnel re-run: N кандидатов сброшено. Запускай hh_batch_review.» (`:1162`). `hh_batch_review` — внутреннее имя, рекрутер его не знает.
- **Исправление:** заменить на понятное «Оценки сброшены; новые отклики будут переоценены при следующей синхронизации».

### P2 — «↩ Вернуть общий шаблон» перезаписывает поле без подтверждения

- **Факт:** обработчик (`:997`) сразу подставляет общий шаблон в `fMessageInstructions`, без `confirm`. Ручная правка теряется.
- **Исправление:** подтверждение.

### P3 — Кнопка сохранения меняет язык после первого сохранения

- **Факт:** в разметке кнопка «Save Funnel» (`:365`, английский), но в `finally` обработчика текст меняется на «Сохранить в контекст» (`:1145`, русский). После первого сохранения язык меняется.
- **Исправление:** единый текст («Сохранить воронку»).

### Что хорошо
- Миграционный черновик явно свечен баннером «Черновик миграции — бот его не использует» (`:372`, `:688`), сохранение в offline заблокировано с понятным title.
- Кнопка «Проверить» валидирует конфиг до сохранения.

## Экран «Холодный поиск» (`/hh/proactive`)

### P2 — Массовый импорт в «просмотренные» без подтверждения

- **Факт:** `importSeen()` (`:776`) отправляет список ID в базу просмотренных без `confirm`. Действие локальное (не наружу), поэтому P2, а не выше.
- **Исправление:** подтверждение с числом ID.

### P2 — «Добавить кандидата» перезагружает страницу

- **Факт:** после добавления `setTimeout(() => location.reload(), 800)` (`:767`). Теряются позиция скролла и несохранённые правки в полях комментариев/поиска.
- **Исправление:** обновлять список без полной перезагрузки.

### Что хорошо
- Переключатель мониторинга имеет явную биполярную подпись («Включить/Отключить мониторинг»).

## Экран «Вакансии» (`/hh/vacancies`)

### P2 — Название обещает список, а это панель запуска

- **Факт:** страница рендерит `vacanciesPageHtml` — форму запуска (цель + «▶ Запустить» + «Отмена») для выбранной вакансии, а не список всех вакансий. При одной вакансии это просто форма.
- **Расхождение:** навигационный пункт «Вакансии» подразумевает список/обзор; рекрутер не видит всех вакансий сразу.
- **Исправление:** либо показывать список вакансий с переходом к запуску, либо переименовать пункт («Запуск»).

## Рекомендуемые задачи (эпики) по сквозным сценариям

1. **Сценарий «массовая работа с кандидатами»** (P0+P1): подтверждение массовой отправки; переименование кнопок баллов; явная область массовых действий; «Отказать все».
2. **Сценарий «защита правок»** (P1+P2): индикатор несохранённого в ATS-редакторе + `beforeunload`; подтверждения у «Перегенерировать все», «Вернуть общий шаблон», «Сбросить к умолчанию».
3. **Сценарий «понятность статусов и подсказок»** (P2+P3): убрать внутренние имена (`hh_batch_review`), единый язык кнопок сохранения, уточнить баннер stale, переименовать «Вакансии».
